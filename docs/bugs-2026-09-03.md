С запуска profk (`e89bd1b2`, 2026-07-08), на 105 значение верное | `/opt/uk/.env` profk, `docker-compose.profk.yml:52` (api, мёртвый CORS-origin) | ✅ `.env` → `https://profk.uz` + recreate `app` (10:04 UTC); compose-строка исправлена; тест кнопки проверяет точный URL |

Обе страницы авторизуют только по initData | `handlers/base.py`, `keyboards/base.py` | ✅ reply-кнопки текстовые; `handlers/webapp_buttons.py` по нажатию шлёт inline web_app-кнопку (initData есть); роль контролёра проверяется в хендлере (BUG-169) |

# Регистрация жителя: обязательный контакт + каскад адреса в TWA — 2026-09-03

Решения владельца после живой проверки BUG-187 (спека
`docs/superpowers/specs/2026-09-03-registration-contact-cascade-design.md`, план
`docs/superpowers/plans/2026-09-03-registration-contact-cascade.md`):

- Телефон только из Telegram-контакта — в боте (житель: контакт → квартира;
  сотрудник: контакт → токен → анкета), в TWA (`requestContact`, контакт
  приходит боту, TWA ждёт `GET /registration/contact-status`). Ручной ввод
  номера удалён везде; `POST /registration/applicant` больше не принимает
  `phone`, берёт `users.phone` (нет → 409).
- Каскад двор → дом → квартира в TWA: `GET /registration/yards`,
  `/yards/{id}/buildings`, `/buildings/{id}/apartments` под тикетом; плоский
  список квартир из `/start` убран.
- Развилка «Я житель / Я сотрудник» сохранена; тестовый аккаунт profk (id=53)
  сброшен владельцем (телефон и заявка на квартиру удалены) для проверки.

Известное ограничение: контакт из TWA не примется, пока у пользователя в боте
висит незавершённый FSM-диалог (лечится `/start`).

# BUG-188 — документы жителя: фото и файлы вне состояния терялись молча — 2026-09-03

**Симптом (владелец):** менеджер «Запросить документы» → житель шлёт фото → бот молчит.

**Диагноз (роутинг проверен `routing_probe.resolve_ctx` по порядку `main.py`):**
1. Уведомление о запросе — голый текст без кнопки и без FSM-состояния
   (`notification_service/documents.py`, `user_management/fsm.py`); `send_to_user`
   не умел `reply_markup`. Фото вне состояния не ловил ни один хендлер (все
   `F.photo`-приёмники привязаны к состояниям) → тишина.
2. На экране выбора типа документа хендлер ловил только `F.text` — фото до
   выбора типа тоже пропадало.
3. Reply-кнопка «Загрузить документы» мертва по генератору — извне в загрузку
   было не попасть.

**Фикс (план `docs/superpowers/plans/2026-09-03-bug188-document-upload-entry.md`):**
inline-кнопка «📤 Загрузить документы» (`keyboards/documents_entry.py`, callback
`docs:upload`) в уведомлении о запросе (язык жителя); колбэк открывает выбор
типа (`onboarding.open_document_upload`); stateless фото/файл в приватном чате
→ подсказка с кнопкой (`catch_stray_document`); фото до выбора типа → подсказка
и повтор клавиатуры (`document_before_type`). Тесты:
`tests/handlers/test_bug188_document_entry.py` (в т.ч. фото в чужих состояниях
по-прежнему уходят своим хендлерам, в группах ловушка не срабатывает).
