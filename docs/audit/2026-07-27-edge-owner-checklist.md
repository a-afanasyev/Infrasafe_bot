# Чек-лист владельцу домена/edge — `PENT-F12`, `PENT-F13`, `PENT-F15`, `PENT-F16`

_Составлен 2026-07-27. Все четыре пункта — конфигурация edge и DNS, вне `/opt/uk`._

Наша зона правок — только каталог приложения (`/opt/uk`) и его контейнеры. Эти четыре
находки внешнего пентеста `profk.uz` живут в `infrasafe-nginx-1` и в DNS-зоне, поэтому
исполнение за владельцем. Ниже — что именно менять и почему; порядок не важен, но
пункты удобно применить одной правкой конфига и одним релоадом.

Отправляется пачкой сознательно: три из четырёх — правки одного и того же nginx-конфига,
и дробить их на три релоада незачем.

---

## 1. `PENT-F16` — конфликтующие security-заголовки (самый содержательный)

**Что нашли:** ответы API несут **два заголовка HSTS** и одновременно
`X-Frame-Options: DENY` и `X-Frame-Options: SAMEORIGIN`.

**Почему это не косметика:** при дублирующихся заголовках поведение зависит от клиента —
современные браузеры обычно берут первый, старые могут взять последний или не применить
политику вовсе. То есть фактическая политика framing'а сейчас не определена, а выглядит
настроенной.

**Что сделать:** назначить edge **единственным владельцем** этих заголовков — снимать
всё, что приходит от upstream (`proxy_hide_header`), и ставить свой канон один раз.

## 2. `PENT-F12` — virtual host принимает произвольный `Host`

**Что нашли:** запрос с SNI `profk.uz` и заголовком `Host: evil.example` вернул страницу
`profk.uz`. Poisoning **не подтверждён** — корневой редирект использует фиксированный
`profk.uz`, — но отвечать содержимым на чужой `Host` не нужно.

**Что сделать:** `default_server`, отвечающий 421 или 444; рабочий vhost — только
`profk.uz` и явный `www.profk.uz`.

## 3. `PENT-F15` — версия nginx на порту 80

**Что нашли:** `Server: nginx/1.31.2` в ответах по HTTP (по HTTPS уже скрыт).

**Что сделать:** `server_tokens off;` во **всех** server-блоках, не только в HTTPS.

## 4. `PENT-F13` — DNSSEC, CAA, OCSP stapling

**Что нашли:** ни DNSSEC, ни записи CAA, ни OCSP stapling.

**Что сделать:** CAA — самая дешёвая и безопасная из трёх (ограничивает, какой УЦ вправе
выпускать сертификаты на домен), делается одной DNS-записью. DNSSEC — на стороне
регистратора/DNS-провайдера. OCSP stapling — директивы nginx.

## Как проверить, что применилось

```bash
# 1 и 3 — заголовки и версия
curl -sI https://profk.uz/uk/api/health | grep -iE 'strict-transport|x-frame|server'
curl -sI http://profk.uz/                | grep -i server

# 2 — чужой Host
curl -s -o /dev/null -w '%{http_code}\n' -H 'Host: evil.example' https://profk.uz/

# 4 — CAA
dig +short CAA profk.uz
```

Ожидаемое: по одному `strict-transport-security` и `x-frame-options`; `server: nginx` без
версии; на чужой `Host` — 421 или 444; в выводе `dig` — непустая запись CAA.
