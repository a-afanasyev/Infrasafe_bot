# Bugs — 2026-08-31

## BUG-184 — Фантомное автосоздание смен: уведомление «Создано N», в БД ноль строк

- **Симптом (репорт владельца):** ежедневное уведомление «🏗️ Автосоздание смен
  завершено. Создано 26 новых смен на ближайшие 7 дней» (05:30 по Ташкенту),
  при этом в дашборде созданных смен нет.
- **Факты:** в `shifts` на profk с 2026-08-29 ни одной новой строки;
  `shifts_id_seq` = max(id) = 77 — не было даже откаченных INSERT. На 105 то же:
  «создано 2» при нуле строк. Логи 105 (00:30 UTC) показали цепочку дословно:
  «Смена None изменилась во время подбора (было None, стало None) —
  автоназначение отменено» → «Ошибка автоназначения …: 'stats'» →
  «Создано 1 смен по шаблону …».
- **Механизм:** `create_shift_from_template` добавлял смены в сессию без
  commit/flush и звал автоназначение. CAS-guard автоназначения (введён в
  программе переназначений, PR #477/478) перечитывает строку по `Shift.id` под
  `FOR UPDATE`; у pending-объекта `id=None` → «строка исчезла» →
  `db.rollback()` — все pending-вставки выброшены. Счётчик же считал питоновские
  объекты списка → фантомный отчёт и уведомление. Поскольку строки не
  сохранялись, дедуп «смены уже существуют» не срабатывал никогда → уведомление
  повторялось каждую ночь. Попутный дефект: строка успеха читала
  `assignment_results['stats']` — ключа нет ни в одной ветке ответа, KeyError
  на каждом запуске уводил поток в fallback.
- **Фикс:** смены коммитятся ДО автоназначения (неназначенная planned-смена —
  валидное состояние; сбой подбора не уничтожает смены; guard получает
  настоящие id и работает как задуман). Лог успеха переведён на реальные ключи
  (`successful_assignments`/`total_shifts`).
- **Тесты:** `tests/services/test_shift_autocreate_persists.py` — настоящий
  sqlite + настоящие planning/assignment сервисы (мок-сессия rollback «не
  замечает» — принципиально нельзя мокать предмет): «создано N» ⇔ N строк;
  назначение доезжает до БД; счётчик `total_created` равен числу строк; сбой
  подбора не уничтожает смены.
