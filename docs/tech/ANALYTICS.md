# Аналитика заявок

> Раскатано на оба прода 2026-10-12 (PR #666, `0a402cbb`, alembic 025).
> План и решения владельца: `~/.claude/plans/proud-discovering-sparrow.md`.

Страница дашборда `/dashboard/analytics` и ежемесячный автоотчёт менеджерам в боте.
Отвечает на вопрос «сколько и как выполнил каждый исполнитель» и даёт выгрузку в CSV.

## 1. Правила зачёта

| Понятие | Как считается |
|---|---|
| Период | Бизнес-даты `YYYY-MM-DD` включительно (Ташкент), переводятся в UTC-окно `business_days_window()`. Не длиннее 5 лет. |
| Создано | `created_at` в окне |
| **Принято** | статус «Принято» и `completed_at` в окне. Засчитывается **текущему** `executor_id`: при переназначении до приёмки заявка уходит новому исполнителю. |
| **Выполнено** | `executed_at` в окне (сдача работы, даже если ещё не приняли), кроме отменённых |
| Возврат | `returned_at` (вернул житель) или `manager_return_reason` (вернул менеджер), бывает «житель и менеджер». **`is_returned` не используется**: планировщик сбрасывает флаг при повторном выполнении и приёмке, у принятых заявок он всегда `False`. Сколько раз возвращали, не хранится. |
| Работа исполнителя | `assigned_at → executed_at`, календарные часы |
| До приёмки | `created_at → completed_at` |
| Срок для норматива | `created_at → executed_at`; у старых заявок без `executed_at` — до `completed_at` |
| Просрочка | срок > `sla_hours[urgency]` |
| Повторная заявка | та же квартира и категория, создана в течение 30 дней после приёмки предыдущей |
| В работе сейчас | статусы «В работе», «Закуп», «Уточнение» на исполнителе, без периода |
| Материалы | расход склада `doc_type=request` по принятым в периоде; сторно не входит (как в карточке заявки) |

Срезы оси — день/месяц/год. Авто-выбор: ≤62 дней → дни, ≤2 лет → месяцы, дальше годы
(`services/request_analytics/period.py`, зеркало на фронте `utils/analyticsPeriod.ts`).
Бакеты считаются в Python по бизнес-дате: `func.date` запрещён гейтом (ARCH-135).

## 2. Поле `requests.executed_at`

Миграция 025, `TIMESTAMPTZ NULL`, без бэкфилла. Пишет планировщик
(`utils/request_workflow/planner.py`) на `EXECUTOR_COMPLETE` / `MANAGER_COMPLETE`;
повтор после возврата перезаписывает. **Данные копятся с 2026-10-12** — у более
старых заявок колонки «Выполнено» и «Работа, ч» пустые («—»).

## 3. API — `/api/v2/requests/stats*`

Все пути — действие `requests.stats` (менеджер), роутер `api/requests/stats_router.py`
без прямого ORM (AST-гейт). Параметры периода `date_from`, `date_to` обязательны
(кроме `/backlog`), ошибки периода — 422.

| Путь | Что отдаёт |
|---|---|
| `GET /stats[?granularity]` | ось `series` (создано/принято), KPI и `previous` (окно той же длины до периода), категории, открытые по статусам (снимок) |
| `GET /stats/executors` | строка на исполнителя: выполнено, принято, возвраты, просрочки, средние времена, оценка, в работе сейчас, материалы |
| `GET /stats/export[?executor_id]` | CSV принятых заявок (строка на заявку) |
| `GET /stats/export/executors` | CSV сводки по исполнителям |
| `GET /stats/quality` | медиана и p90 срока по срочности, просрочки, возвраты по категориям, оценки 1–5, последние 10 отзывов |
| `GET /stats/backlog` | открытые сейчас: возраст, очереди, 20 самых старых |
| `GET /stats/addresses` | топ-10 домов и дворов по созданным, повторные заявки |
| `GET /stats/channels[?granularity]` | созданные по `source`, с разбивкой по срезу |
| `GET /stats/costs` | материалы по категориям и домам |
| `GET /stats/report[?lang&organization&signer]` | отчёт для проверяющих органов, .xlsx (§4a) |

Список заявок `GET /api/v2/requests` принимает `accepted_from` + `accepted_to`
(только парой) — так строка таблицы исполнителей раскрывает его заявки за период.

## 4. CSV

`services/request_analytics/csv_export.py`, формат как у склада: разделитель `;`,
BOM для Excel, `escape_csv_cell` на всех строках от людей, лимит 10 000 строк (без
пометки об обрезке). Числа с запятой, даты — `ДД.ММ.ГГГГ ЧЧ:ММ` по Ташкенту.
Колонки выгрузки заявок: номер, исполнитель, категория, адрес, срочность, источник,
даты создания/назначения/выполнения/приёмки, часы работы и до приёмки, норматив,
просрочена, оценка, отзыв, отчёт исполнителя (до 500 символов), фото работ,
возвращали, кто вернул, причина, материалы, ссылка на карточку
(`{FRONTEND_URL}/uk/dashboard?request=N`).

## 4a. Отчёт для проверяющих органов (.xlsx)

Для хокимията, налоговой и т. п. Кнопка «Отчёт для проверяющих» над вкладками
аналитики (`components/analytics/OfficialReportDialog.tsx`): период — текущий
выбор страницы, организация и ФИО руководителя (помнятся в `localStorage`),
язык RU/UZ. Данные — `services/request_analytics/official_report.py`, рендер —
`official_xlsx.py` (openpyxl). Правила зачёта те же, что в §1.

Листы: **Сводка** (поступило/выполнено/в срок/с нарушением/доля в срок, средний
срок, возвраты, оценки; состояние поступивших за период на дату формирования;
таблицы по видам работ и срочности + диаграмма; примечания; блок подписей и М.П.,
печать на один лист A4), **Динамика** (дни для периода < 31 дня, иначе месяцы;
столбчатая диаграмма), **По домам** (дом через квартиру или напрямую; строка «без
привязки»), **Реестр** (строка на выполненную заявку, по дате приёмки: номер, даты,
адрес, вид работ, содержание и выполненные работы до 500 символов, исполнитель,
срок/норматив/соблюдён; автофильтр). Даты — настоящие даты Excel по Ташкенту.
Реестр — до 10 000 строк с красной пометкой об обрезке, итоги — по всем.
Персональных данных жителей (ФИО, телефоны) в отчёте нет; телефоны, вписанные
в содержание и выполненные работы, маскируются (`[телефон]`, `utils/pii.py`). Текст от людей —
только как текст (без формул), управляющие символы вычищаются.

## 5. Нормативы сроков

Секция `sla_hours` в JSON `auto_manager_config` (`services/auto_manager/config.py`),
дефолт critical 4 / high 24 / medium 72 / low 168 ч, целые 1..8784. Без строки
конфига (как на 105) действует дефолт. Редактор — на вкладке «Сроки и качество»
(видят те, у кого `auto_manager.configure`); PUT идёт через тот же
`/api/v2/auto-manager-config`.

## 6. Автоотчёт в бот

`services/request_analytics/monthly_report.py`, джоба `monthly_report` в
`utils/shift_scheduler.py`: **1-го числа в 09:00 по Ташкенту** каждому активному
менеджеру — CSV за прошлый календарный месяц (тот же `build_completed_csv`) и
сводка на его языке (ключи `analytics_report.*` в локалях бота). Подпись с
`parse_mode="HTML"`, имена экранируются. Повтор за месяц отсекает ключ Redis
`report:monthly:YYYY-MM` (без Redis — fail-open). Сбой доставки одному менеджеру
не останавливает остальных, текст ошибки Bot API не логируется.

Ручной прогон (например, проверка): `send_monthly_report(bot, force=True)`.

## 7. Фронт

`pages/AnalyticsPage.tsx` (оболочка, вкладка в `?tab=`), компоненты
`components/analytics/*`, хуки `hooks/useAnalytics.ts` (запросы только открытой
вкладки), CSV-скачивание `utils/download.ts`. Вкладки: Обзор, Исполнители, Сроки и
качество, Хвост и адреса, Каналы и затраты. Зона под гейтом i18n-чистоты.

## 8. Известные ограничения

- Зачёт текущему исполнителю: прежний при переназначении заявку теряет (история
  назначений неполная, честно восстановить нельзя).
- Время — календарные часы, ночи и выходные входят; привязки к сменам нет.
- «Адреса» не учитывают заявки только с текстовым адресом (legacy).
- «Последние действия» убраны: честного журнала переходов статусов нет.
