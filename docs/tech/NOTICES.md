# Новости и уведомления (`notices`)

> _Последнее редактирование: 2026-11-14_ · этап 1 из трёх (план владельца 2026-11-14).

## Что это

Единый источник всего, что УК сообщает жителям: ручные новости, плановые отключения,
одобренные новости каналов (news-watch), а с этапа 3 — отключения, объявленные сотрудником.
Раздел дашборда «Новости и уведомления» (`/dashboard/notices`) заменил секции «Объявления» и
«Плановые работы» редактора витрины и пункт меню «Отключения».

Жители видят записи **прежними блоками** — «Новости» и «Ближайшие работы» на табло, главной
`/home` и в TWA. Контракт `GET /api/v2/public/board-config` и `GET /api/v2/announcements` не
менялся: списки `announcements` / `planned_works` сервер собирает из таблицы, а не из JSON
`board_config`.

## Модель

Таблица `notices` (миграция `033`, модель `database/models/notice.py`):

| Поле | Смысл |
|---|---|
| `kind` | `news` — новость; `outage` — отключение (с `resource`: вода, отопление, электричество, газ, интернет, другое) |
| `source` | `manual` — менеджер; `news_watch` — одобренная новость канала (`news_item_id`); `staff` — сотрудник (этап 3) |
| `status` | `draft` → `published` → `closed` |
| `publish_at` | когда показать жителям; в будущем = отложенная публикация |
| `starts_at` / `ends_at` / `all_day` | окно отключения |
| `expires_at` | когда убрать с витрины; пусто — до конца окна (`ends_at`), а без окна — пока не закроют. Копию `ends_at` сюда не пишем: продлили отключение — показ продлился сам |
| `scope`, `scope_ids`, `broadcast_*` | адресаты и outbox рассылки — используются с этапа 2 |

Состояние для интерфейса (`state`) — производное: `draft` · `scheduled` (опубликована, срок
публикации не наступил) · `active` · `expired` (срок показа истёк) · `closed`.

## Что куда попадает на витрине

`services/notices/board.py`:

- новость → «Новости»;
- отключение с окном → «Ближайшие работы» (сегодняшние и будущие; идущее не первый день
  показывается сегодняшним числом);
- отключение из канала или от сотрудника — дополнительно в «Новости», важным;
- строка «Ближайших работ» обрезается по показанному дню: отключение, начавшееся вчера или
  заканчивающееся завтра, сегодня идёт с `00:00` / до `23:59`;
- публичная выдача ограничена: `MAX_ANNOUNCEMENTS` новостей и `MAX_PLANNED_WORKS` работ, свежие выше.

`board_config.announcements` и `planned_works` больше не читаются и не пишутся: миграция `033`
перенесла их в таблицу, `merge_and_save_board_config` игнорирует эти ключи в теле PUT (старая
вкладка редактора не вернёт их в JSON).

## API

`/api/v2/notices`, действие `notices.manage` (по умолчанию менеджер):

| Метод | Путь | Что делает |
|---|---|---|
| GET | `` | лента; `kind`, `status`, окно календаря `from`/`to` |
| POST | `` | создать; `publish: true` — опубликовать сразу или к `publish_at` |
| PATCH | `/{id}` | правка; `null` очищает необязательное поле; проверяется итоговая запись, а не тело (422: отключение без начала или ресурса, конец раньше начала, опубликованная без заголовка); закрытую править нельзя (409) |
| POST | `/{id}/publish` | опубликовать черновик |
| POST | `/{id}/close` | снять с показа (запись остаётся в ленте и календаре) |
| DELETE | `/{id}` | только черновик (409 для опубликованной) |

Даты принимаются только со смещением зоны и хранятся в UTC. Управляющие символы и невидимые
метки направления письма в текстах отклоняются (422).

⚠️ Префикс `/api/v2/notices` нужно заявить в edge-allowlist на обеих площадках **до** выкатки.

## Связь с news-watch

Одобрение новости канала (`services/news_watch/pipeline._publish_item`) создаёт запись
`notices` (`source=news_watch`, одна на новость). Показывается до конца названного окна, без
окна — трое суток (раньше такие объявления висели на табло бессрочно). Рассылка жителям пока
идёт прежним воркером по `news_items` — на `notices` она переедет на этапе 2.
