# Новости и уведомления (`notices`)

> _Последнее редактирование: 2026-11-15_ · три этапа плана владельца от 2026-11-14.

## Что это

Единый источник всего, что УК сообщает жителям: ручные новости, плановые отключения,
одобренные новости каналов (news-watch), а с этапа 3 — отключения, объявленные сотрудником.
Раздел дашборда «Новости и уведомления» (`/dashboard/notices`) заменил секции «Объявления» и
«Плановые работы» редактора витрины и пункт меню «Отключения».

Жители видят записи **прежними блоками** — «Новости» и «Ближайшие работы» на табло, главной
`/home` и в TWA. Контракт `GET /api/v2/public/board-config` и `GET /api/v2/announcements` не
менялся: списки `announcements` / `planned_works` сервер собирает из таблицы, а не из JSON
`board_config`.

## Модель

Таблица `notices` (миграция `033`, модель `database/models/notice.py`):

| Поле | Смысл |
|---|---|
| `kind` | `news` — новость; `outage` — отключение (с `resource`: вода, отопление, электричество, газ, интернет, другое) |
| `source` | `manual` — менеджер; `news_watch` — одобренная новость канала (`news_item_id`); `staff` — сантехник на смене (этап 3) |
| `status` | `draft` → `published` → `closed` |
| `publish_at` | когда показать жителям; в будущем = отложенная публикация |
| `starts_at` / `ends_at` / `all_day` | окно отключения |
| `expires_at` | когда убрать с витрины; пусто — до конца окна (`ends_at`), а без окна — пока не закроют. Копию `ends_at` сюда не пишем: продлили отключение — показ продлился сам |
| `scope`, `scope_ids` | адресаты: `all` — все жители, `yards` / `buildings` — id дворов / домов справочника |
| `broadcast_*` | outbox рассылки в Telegram: `none` — не заказана, `pending` → `running` → `done` / `failed` |

Состояние для интерфейса (`state`) — производное: `draft` · `scheduled` (опубликована, срок
публикации не наступил) · `active` · `expired` (срок показа истёк) · `closed`.

## Что куда попадает на витрине

`services/notices/board.py`:

- новость → «Новости»;
- отключение с окном → «Ближайшие работы» (сегодняшние и будущие; идущее не первый день
  показывается сегодняшним числом);
- отключение из канала или от сотрудника — дополнительно в «Новости», важным;
- строка «Ближайших работ» обрезается по показанному дню: отключение, начавшееся вчера или
  заканчивающееся завтра, сегодня идёт с `00:00` / до `23:59`;
- публичная выдача ограничена: `MAX_ANNOUNCEMENTS` новостей и `MAX_PLANNED_WORKS` работ, свежие выше.

`board_config.announcements` и `planned_works` больше не читаются и не пишутся: миграция `033`
перенесла их в таблицу, `merge_and_save_board_config` игнорирует эти ключи в теле PUT (старая
вкладка редактора не вернёт их в JSON).

## API

`/api/v2/board-config/notices`, действие `notices.manage` (по умолчанию менеджер):

| Метод | Путь | Что делает |
|---|---|---|
| GET | `` | лента; `kind`, `status`, окно календаря `from`/`to` |
| POST | `` | создать; `publish: true` — опубликовать сразу или к `publish_at` |
| PATCH | `/{id}` | правка; `null` очищает необязательное поле; проверяется итоговая запись, а не тело (422: отключение без начала или ресурса, конец раньше начала, опубликованная без заголовка); закрытую править нельзя (409) |
| POST | `/{id}/publish` | опубликовать черновик |
| POST | `/{id}/close` | снять с показа (запись остаётся в ленте и календаре) |
| DELETE | `/{id}` | только черновик (409 для опубликованной) |
| GET | `/audience?scope=&ids=` | сколько жителей получит рассылку с такими адресатами |
| POST | `/{id}/retry-broadcast` | повторить рассылку, исчерпавшую попытки (409, если она не `failed` или запись снята с показа) |

Даты принимаются только со смещением зоны и хранятся в UTC. Управляющие символы и невидимые
метки направления письма в текстах отклоняются (422).

Префикс вложен в `/api/v2/board-config` намеренно: edge обеих площадок пропускает его целиком
(пробы 2026-11-15: GET/POST/PATCH/DELETE доходят до FastAPI), правка allowlist не нужна. Новый
верхний префикс `/api/v2/notices` edge режет (404 `text/html`).

## Связь с news-watch

Одобрение новости канала (`services/news_watch/pipeline._publish_item`) создаёт запись
`notices` (`source=news_watch`, одна на новость). Показывается до конца названного окна, без
окна — трое суток (раньше такие объявления висели на табло бессрочно). Рассылку жителям по
новостям каналов ведёт очередь `news_items` (всем, по настройкам news-watch); очередь
`notices` такие записи пропускает, чтобы житель не получил сообщение дважды.

## Фронт

`pages/NoticesPage.tsx` — вкладки «Лента», «Отключения», «Календарь», «Из каналов» (прежняя страница
«Отключения», при `VITE_NEWS_WATCH_ENABLED`). Форма — `components/notices/NoticeForm.tsx`,
календарь — `NoticeCalendar.tsx`, чистая модель — `noticeModel.ts`. Старый адрес
`/dashboard/news-watch` перенаправляет на вкладку «Из каналов».

Вкладка «Отключения» (`components/notices/OutageStatus.tsx`, `?tab=outages`) — пульт менеджера:
что отключено сейчас (все виды и источники), кто объявил, с какого времени, обещанный срок
(красным, если он вышел, а запись не закрыта) и «включено за последние сутки» с именем
закрывшего. Кнопка «Воду включили» у отключения от сантехника — это `POST /{id}/close`: запись
закрывается, жители получают сообщение о включении; у остальных — «Снять с показа» без
рассылки. На ярлыке вкладки — счётчик идущих отключений. Имена отдаёт лента
(`created_by_name`, `closed_by_name` в `NoticeOut`).

## Рассылка в Telegram (этап 2)

Менеджер ставит в форме «Разослать в Telegram» (`broadcast: true` в теле создания или правки)
и выбирает адресатов. Запись встаёт в очередь (`broadcast_status=pending`), её забирает
воркер `api/notices/broadcast.py`.

- **Механика общая** с новостями каналов: `api/news_watch/broadcast.py` обслуживает две
  очереди (`Outbox`) — `news_items` и `notices`. Курсор по `users.id`, 429 → `retry_after`,
  5 попыток с бэкоффом, недоставленные — в `broadcast_details.retry`, рестарт без дублей.
- **Когда уходит**: когда запись видна жителям (`visible_clause`). Отложенная — в момент
  `publish_at`; черновик, закрытая и истёкшая не рассылаются.
- **Кому** (`services/notices/audience.py`): `all` — все одобренные жители и чаты домов;
  `yards` / `buildings` — жители с одобренной привязкой к действующей квартире во дворе / доме,
  чаты домов не используются. Общие условия: роль жителя, одобрен, не удалён, бот не заблокирован.
- **Что**: значок, заголовок, окно и место отключения, текст — блоком на русском и, если
  заполнен заголовок, на узбекском. Всё проходит `html.escape` в точке вывода.
- **Без дублей**: записи `source=news_watch` эта очередь не берёт — их рассылает очередь
  `news_items`. Разосланную запись правка текста повторно не отправляет; флаг `broadcast`
  меняет только ещё не начатую рассылку.
- Цикл запускается в `api/lifecycle.py` всегда (раз в 30 с), от `NEWS_WATCH_ENABLED` зависит
  только очередь новостей каналов.

## Отключения от сантехника (этап 3)

Сантехник перекрыл воду — объявляет это сам, жители дома узнают сразу. Объявляют только в
TWA — обычном и простом режиме (кнопка «Отключил воду» на экране смены,
`frontend/src/twa/outage/`); в боте кнопки объявления нет (решение владельца 2026-11-15).
Кнопку видит только сантехник: на смене — рабочую, вне смены — неактивную с подсказкой
«Сначала начните смену». Правила — в `services/notices/outages.py`, TWA ходит через API:

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/outages/options` | можно ли объявить (`allowed`, `reason`), дворы и дома, незакрытые отключения |
| POST | `/outages` | объявить: `resource` (`water` / `heating`), `building_ids`, `duration` (`1h` / `2h` / `4h` / `day` / `unknown`) |
| POST | `/outages/{id}/close` | «включили» |

- **Кто может**: действие `outages.announce` (по умолчанию исполнитель) и сверх него —
  специализация `plumber` (только сантехник; специалист по отоплению — нет), одобренный аккаунт и активная смена
  (`utils/shifts.is_on_shift_now_async`, тот же предикат, что у пула заявок). Иначе 403
  `not_plumber` / `no_active_shift`. Электричество и газ объявляет менеджер из веба.
- **Что создаётся**: запись `kind=outage`, `source=staff`, `scope=buildings`, опубликована,
  `broadcast_status=pending`. В очереди такие записи идут раньше обычных (`Outbox.priority`).
  Заголовок «Отключена вода — адреса домов» (RU/UZ), окно от «сейчас»; «до конца дня» — 23:59
  по времени объекта, `unknown` — без конца.
- **Не уходит с витрины сама**: срок — оценка сантехника, поэтому `visible_clause` для
  `source=staff` отключений конец окна не учитывает — запись висит, пока её не закроют.
- **Ограничения**: то же отключение по тому же дому второй раз не объявить (409
  `already_open`); не больше `MAX_PER_HOUR` (6) объявлений в час на сотрудника (429 `too_many`).
- **Кому**: жителям выбранных домов и копией всем менеджерам (`Plan.also` в общем воркере).
- **«Включили»**: закрывает запись и ставит в очередь новость «Воду включили — адреса» тем же
  адресатам (на витрине 6 часов). Закрыть может автор — и после смены — или любой сантехник
  на смене (сменщик); иначе 403 `not_yours`. Менеджер закрывает тем же путём кнопкой «Снять с
  показа» в дашборде. Если «отключили» ещё не ушло, оно снимается, а «включили» не рассылается.
- **Ответ сантехнику** — `OutageNoticeOut` без `broadcast_details` (там id жителей и чатов).
- **Напоминания автору** (`services/notices/outage_reminders.py`), тик планировщика бота раз в
  10 минут, по одному разу: срок вышел — «Уже включили?»; смена автора закончилась любым
  способом (кнопкой, по расписанию, менеджером) — «Смена закончена, а отключение не закрыто».
  В обоих — кнопка «✅ Включили» (`handlers/outages.py` — единственное, что есть в боте).
- Аудит: `outage_announced`, `outage_closed`. Офлайн-очередь простого режима для отключений
  не используется: объявление уходит сразу или показывает ошибку.
