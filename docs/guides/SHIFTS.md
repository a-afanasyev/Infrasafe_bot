# Смены: как это работает

> Описательный документ для менеджера и администратора. Составлен по коду
> (ветка main, 2026-08-31) с проверкой работоспособности: 923 автотеста домена
> зелёные, фоновые джобы и данные проверены на живом проде profk. Findings
> ревью — в конце документа.

## 1. Что такое смена

Смена — это запись «сотрудник работает в такое-то окно времени» (таблица
`shifts`). У смены есть:

- **Исполнитель** (`user_id`) — может быть пустым: «незаполненная смена»,
  которую ещё предстоит закрыть назначением.
- **Плановое время** (`planned_start_time`/`planned_end_time`) — из шаблона или
  расписания; **фактическое** (`start_time`/`end_time`) — когда реально шла.
- **Статус** — см. жизненный цикл ниже.
- **Тип** (`shift_type`): regular / emergency / overtime / maintenance.
- **Специализации** (`specialization_focus`) — какие компетенции закрывает
  (электрик, сантехник, …); **зоны покрытия** и **географическая зона**.
- **Лимит заявок** (`max_requests`, по умолчанию 10) и текущая загрузка
  (`current_request_count`).
- **Метрики** (заполняются аналитикой): выполненные заявки, среднее время
  выполнения/реакции, эффективность, оценка качества.

Все часы в шаблонах — «стенка» бизнес-зоны объекта (Ташкент): шаблон «08:00»
означает 08:00 по местному, в БД хранится UTC-инстант.

## 2. Жизненный цикл

```
planned ──(окно наступило + есть исполнитель)──► active ──(end_time истёк)──► completed
   │                                               ▲
   └──(кнопка «Начать смену» активирует ЕЁ) ───────┘
ad-hoc: «Начать смену» без расписания ──► active (end_time пуст) ──(кнопка «Завершить»)──► completed
```

- **planned** — создана из шаблона/расписания/вручную, ещё не идёт.
- **active** — идёт сейчас. Только исполнители в active-смене видны фильтру
  «кто на смене», получают заявки и предлагаются при назначении.
- **completed** — завершена (по времени или вручную).

Переводы **выполняет джоба активации каждые 3 минуты** (решение владельца
2026-08-24): planned с исполнителем в наступившем окне → active; active с
истёкшим `end_time` → completed. Ad-hoc-смены (открытые кнопкой без
расписания) не имеют `end_time` — их завершает сам сотрудник или менеджер.

Статус «cancelled» в модели предусмотрен, но сейчас ни один живой путь его не
ставит (см. findings): менеджер на дашборде именно **удаляет** смену
(hard delete), а не отменяет.

## 3. Откуда берутся смены

### 3.1. Шаблоны (основной путь)

Шаблон (`shift_templates`) описывает повторяющуюся смену: название, час
начала/длительность, требуемые специализации, зоны, `min_executors` (сколько
смен создать на день), приоритет и режим повторения:

- **weekday** — по дням недели (`days_of_week`, например Пн–Сб);
- **cycle** — «N рабочих / M выходных» (например сутки через трое).

Флаг `auto_create` включает шаблон в автосоздание. Управление шаблонами:
бот («Управление сменами → Управление шаблонами»: создать, посмотреть,
редактировать) и дашборд (CRUD `/api/v2/shifts/templates` + «создать смену из
шаблона»).

### 3.2. Автосоздание (ежедневно 05:30 по Ташкенту)

Джоба берёт все активные шаблоны с `auto_create` и создаёт по ним смены на
7 дней вперёд (в пределах `advance_days` шаблона). Дубли исключены: если на
дату по шаблону смены уже есть — день пропускается. Сразу после создания
запускается автоназначение исполнителей (см. §4). Если создано больше 10 смен,
менеджерам приходит уведомление «Автосоздание смен завершено».

### 3.3. Еженедельное планирование (понедельник 13:00 по Ташкенту)

Планирует следующую неделю по тем же шаблонам и обновляет таблицу расписания
`shift_schedules` (план/факт покрытия по дням, прогноз заявок). Менеджерам
уходит итоговое уведомление.

### 3.4. Вручную менеджером

- **Бот**: «Управление сменами → Планирование смен» — создать по шаблону на
  выбранную дату, спланировать неделю, автопланирование (завтра / неделя /
  месяц) с подтверждением.
- **Дашборд**: страница «Смены» — создание смены формой (исполнитель, время,
  тип, специализации, лимит), создание из шаблона, редактирование полей,
  переназначение, завершение, удаление.

### 3.5. Ad-hoc сотрудником

Кнопка «🟢 Начать смену» (бот «Мои смены», TWA «Моя смена»). Если у сотрудника
есть **запланированная** смена, чьё окно уже идёт, кнопка активирует ЕЁ (а не
создаёт дубль). Если запланированной нет — создаётся ad-hoc active-смена без
`end_time`. Разрешено несколько активных смен одновременно (сотрудник может
закрывать несколько компетенций).

## 4. Назначение исполнителей

- **При создании из шаблона** — автоназначение сразу: скоринг кандидатов
  (специализация, текущая загрузка, конфликты по времени), победитель
  назначается, проигравшие причины записываются в аудит
  (`SHIFT_AUTO_ASSIGNED`). Защита от гонок: строка смены перечитывается под
  блокировкой — ручное назначение менеджера, сделанное параллельно, не
  затирается.
- **Джоба «пустые смены» каждые 15 минут** — ищет planned-смены без
  исполнителя, начинающиеся в ближайшие 48 часов (до 10 за тик), и пытается
  назначить.
- **Перебалансировка ежедневно 11:00 по Ташкенту** — выравнивает назначения
  на сегодня и завтра.
- **Вручную**: бот («Назначить исполнителей»: по одному, массово по
  специализации/приоритету/периоду) и дашборд (переназначение в карточке
  смены). Сотрудник получает уведомление о назначении.

## 5. Уведомления

| Кому | Что | Когда |
|---|---|---|
| Исполнителю | Напоминание о предстоящей смене | Один раз, за ~2 часа до начала (джоба каждые 30 мин круглосуточно) |
| Исполнителю | «Вы назначены на смену» | При автоназначении |
| Исполнителю/менеджеру | Старт/завершение смены | По кнопкам |
| Менеджерам | Автосоздание (>10 смен), еженедельное планирование, истёкшие передачи, крупные автоназначения заявок, синхронизация | По факту работы джоб |

## 6. Передачи смен

Сотрудник не может выйти — он **передаёт** смену:

1. **Исполнитель** («Мои смены → Передача смены»): выбирает смену
   (planned/active), причину (болезнь/личное/…), срочность, комментарий →
   передача в статусе `pending`. Одновременно активной может быть только одна
   передача на смену.
2. **Менеджер** (бот «Передачи» или дашборд `/shifts` → «Передачи»): назначает
   получателя из подходящих исполнителей → `assigned`. Может и напрямую
   переназначить смену без цепочки согласий.
3. **Получатель**: принимает (`completed` — смена и все её активные заявки
   переезжают к нему, обе стороны и менеджер уведомляются) или отклоняет
   (возврат к менеджеру, счётчик попыток до 3).
4. **Просрочка**: передачи без ответа больше 24 часов обрабатываются джобой
   (каждые 2 часа) автоматически, менеджеры уведомляются.

Завершённые/отменённые передачи старше 30 дней удаляются еженедельной очисткой
(воскресенье ночью).

## 7. Смены и заявки

- Назначение заявок исполнителям учитывает «кто сейчас на смене»: фильтр «на
  смене» в подборе, карточка сотрудника, профиль.
- **Автоматический менеджер** (тик каждые 2 минуты, тумблер владельца в боте:
  «Управление сменами → Автоменеджер») — назначает дежурных на ночные заявки.
- **Синхронизация назначений** (каждые 30 минут) — переназначает заявки в
  соответствии с фактическими сменами на сегодня/завтра; о переназначениях
  уведомляет менеджеров.
- Джоба «автоназначение заявок исполнителям смен» (каждые 10 минут) —
  фактически **выключена**: её движок фильтрует по устаревшему статусу и
  никогда ничего не назначает (задокументировано в коде; тумблер
  автоназначения её честно гасит).

## 8. Аналитика

- **Бот**, «Управление сменами → Аналитика и отчёты»: недельная аналитика,
  месячный отчёт, прогноз загрузки, рекомендации по оптимизации, анализ
  эффективности (по сменам и исполнителям: скоринг эффективности, паттерны по
  дням, рекомендации).
- **Дашборд**: `/api/v2/shifts/stats` — сводная статистика; страница «Смены» —
  представления «день» (таймлайн), «неделя» (сетка + **тепловая карта покрытия**
  по часам), «месяц»; карточка смены с метриками (загрузка %, приоритет,
  выполненные заявки, эффективность, оценка).
- Таблица `shift_schedules` копит план/факт покрытия и точность прогноза по
  дням — её пишет еженедельное планирование.

## 9. Интерфейсы по ролям

**Исполнитель**:
- Бот «Мои смены»: текущие смены, расписание на неделю, история, передача
  смены; в карточке — начать/завершить смену.
- TWA (мини-приложение): «Моя смена» — старт/стоп с таймером, ближайшие
  запланированные.

**Менеджер** (роль manager):
- Бот «Управление сменами»: планирование, аналитика, шаблоны, назначение
  исполнителей, автоменеджер.
- Дашборд: страница «Смены» (все представления, CRUD, передачи), страница
  «Сотрудники» (инвайты, одобрение, блокировка — отдельный модуль).

**Администратор** дополнительно: тумблеры автоменеджера/автоназначения,
шаблоны, наблюдение за джобами (логи контейнера `uk-management-bot`,
`docker logs … | grep executed`).

## 10. Фоновые джобы (сводно)

Время указано и в UTC (планировщик), и по Ташкенту (бизнес-зона).

| Джоба | Расписание (UTC / Ташкент) | Что делает |
|---|---|---|
| Активация по расписанию | каждые 3 мин | planned→active, active→completed |
| Автосоздание смен | 00:30 / 05:30 | смены из шаблонов на 7 дней |
| Перебалансировка | 06:00 / 11:00 | выравнивание назначений сегодня/завтра |
| Истёкшие передачи | каждые 2 ч | автообработка передач >24 ч |
| Очистка | вс 02:00 / 07:00 | передачи старше 30 дней |
| Напоминания о сменах | каждые 30 мин, круглосуточно | один раз, за ~2 ч до начала |
| Пустые смены | каждые 15 мин | автоназначение (окно 48 ч) |
| Автоназначение заявок | каждые 10 мин | мёртвый движок, выключено |
| Синхронизация назначений | каждые 30 мин | заявки ↔ фактические смены |
| Автоменеджер (дежурные) | каждые 2 мин | ночные заявки → дежурные |
| Еженедельное планирование | пн 08:00 / 13:00 | следующая неделя + расписание |

## 11. Findings ревью (2026-08-31)

Проверено: 923 автотеста домена (все зелёные), живые джобы и данные profk
(9 шаблонов, 56 строк расписания, 81 смена; активация подтверждена логом
«активировано 5»), полный цикл создание→назначение→активация прогнан на проде
после фикса BUG-184.

Дефекты, найденные ревью (на момент написания НЕ исправлены):

1. ~~**Мёртвые кнопки в карточке смены исполнителя (бот)**~~ — ✅ исправлено
   2026-08-31. При фиксе выяснилось, что их не 4, а **11** (скаффолд
   2025-09-26): «Связаться с менеджером», «Отклонить смену» (planned);
   «Перерыв», «Мои заявки», «Отметить локацию», «Заметка», «SOS» (active);
   «Отчёт», «Обработанные заявки», «Расчёт оплаты» (completed); «Детали» и
   «Поделиться» (всегда). Ни у одной не было хендлера — нажатие молча ничего
   не делало. Итог: 10 кнопок убраны, «Мои заявки» реализована — открывает
   существующий раздел заявок с фильтром «активные». Возврат кнопки — только
   вместе с хендлером (гейт `test_shift_card_buttons.py`).
2. ~~**Утренние напоминания о сменах не отправляются.**~~ — ✅ исправлено
   2026-08-31. Джоба работала 08:00–20:30 **UTC** (13:00–01:30 по Ташкенту),
   а типовые смены начинаются 08:00–09:00 местного — окно «за 2 часа» было
   целиком вне графика. Теперь джоба тикает круглосуточно каждые 30 минут, а
   выборка сужена до среза `[now+90м, now+120м)`: каждая смена получает РОВНО
   ОДНО напоминание, за ~2 часа до начала (раньше дневные смены напоминались
   до пяти раз подряд).
3. ~~**Джоба «пустые смены» теряет счётчик и шумит ошибкой**~~ — ✅ исправлено
   2026-08-31: читала `result['stats']['assigned']`, а ключа `stats` в ответе
   сервиса не существует (тот же класс, что BUG-184; второй экземпляр).
   Назначения проходили, но каждый непустой тик падал KeyError. Переведена на
   реальный ключ `successful_assignments`.
4. **Статус «cancelled» недостижим** — кнопка «Отменить» смены живёт только в
   нерендерящейся клавиатуре; на дашборде смена удаляется физически.
5. **Код-мусор**: клавиатуры `get_shift_details_keyboard` /
   `get_executor_selection_keyboard` (бот, менеджер) не вызываются ни одним
   хендлером — вместе со своим набором callback'ов это мёртвый код.

Исправлено в ходе ревью (уже на проде): **BUG-184** — фантомное автосоздание
(джоба рапортовала «создано 26», БД пустая; смены теперь коммитятся до
автоназначения, PR #517).
