# BUG-190 — вкладка «Календарь» лифта: «Все» по состоянию даёт ошибку (profk) — 2026-09-14

**Симптом.** В карточке лифта на вкладке «Календарь» выбор «Все» в фильтре
состояния (и любой вид работ при таком состоянии) показывает «Ошибка»;
«Запланировано» / «Выполнено» / «Отменено» отображаются нормально.

**Воспроизведение (логи `uk-management-api` на profk за 72 ч).**

```
GET /uk/api/v2/elevators/208/occurrences?kind=maintenance&state=all&lang=ru  422
GET /uk/api/v2/elevators/208/occurrences?state=all&lang=ru                   422
```

Тело 422: `Input should be 'planned', 'done' or 'cancelled'` (loc `query.state`,
input `all`).

**Корень.** Два роута графика описаны разными типами `state`: общий календарь
`GET /occurrences` — `CalendarState` (с `all`, маппится в «без фильтра»), а
per-elevator `GET /{elevator_id}/occurrences` — `Optional[OccurrenceState]`
(без `all`). Фронт `ElevatorCalendarTab` шлёт одно и то же `state=all` в оба.
Домен (`_occurrences_stmt`) при `state=None` фильтр не ставит, то есть
семантика уже была, не хватало только приёма значения на HTTP-слое.

**Правка.** `uk_management_bot/api/elevators/router_calendar.py::list_occurrences`:
`state: Optional[CalendarState]`, `all` → `None` (как в `calendar_all`).
Снапшот `docs/tech/openapi.json` дополнен вручную по узлу (локальный pydantic
теряет `pattern` у Decimal — генерировать снапшот целиком только из CI-образа).

Тест: `tests/api/test_elevators_status_calendar.py::test_list_occurrences_state_all_is_unfiltered`
(красный до правки на том же 422, зелёный после; `state=x` по-прежнему 422).

Раскатка: пересборка образа `api` на profk (миграций нет, edge-allowlist не
меняется — префикс уже заявлен).
