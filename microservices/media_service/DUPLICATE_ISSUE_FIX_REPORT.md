# ОТЧЕТ ОБ ИСПРАВЛЕНИИ ПРОБЛЕМЫ С ДУБЛИКАТАМИ МЕЖДУ ЗАЯВКАМИ

## 🚨 ПРОБЛЕМА

**Дата обнаружения:** 6 октября 2025  
**Описание:** При загрузке одного и того же файла (например, `дамас.jpg`) на разные заявки через HTTP API, система перетирала предыдущие заявки и оставляла только последний вариант.

**Симптомы:**
- Одинаковый файл на разных заявках получал один и тот же ID в базе данных
- При загрузке файла на новую заявку, предыдущие заявки теряли доступ к файлу
- Файлы "переезжали" от одной заявки к другой

## 🔍 АНАЛИЗ ПРИЧИН

### 1. Неправильная логика обработки дубликатов
**Файл:** `app/services/media_storage.py` (строки 540-547)  
**Проблема:** При обнаружении существующего файла с таким же `telegram_file_id`, система обновляла метаданные существующего файла вместо создания нового.

```python
# НЕПРАВИЛЬНО:
if existing_file:
    existing_file.request_number = request_number  # Перетирает данные!
    existing_file.category = category
    # ...
    return existing_file
```

### 2. Уникальное ограничение в БД
**Проблема:** В базе данных было уникальное ограничение только на `telegram_file_id`, что не позволяло создавать отдельные записи для разных заявок.

```sql
-- НЕПРАВИЛЬНО:
UNIQUE (telegram_file_id)
```

### 3. Логика проверки дубликатов
**Проблема:** Система проверки дубликатов работала правильно, но основная логика загрузки обходила её, обновляя существующие записи.

## ✅ ИСПРАВЛЕНИЯ

### 1. Изменение логики обработки файлов
**Файл:** `app/services/media_storage.py`  
**Изменение:** Убрана логика обновления существующих файлов, теперь всегда создаются новые записи.

```python
# ПРАВИЛЬНО:
# Создаем новую запись для каждой заявки
# Уникальное ограничение в БД предотвратит дубликаты в рамках одной заявки
logger.info(f"Creating new media record for request {request_number}")
```

### 2. Исправление уникального ограничения в БД
**Изменение:** Заменено глобальное уникальное ограничение на составное ограничение.

```sql
-- УДАЛЕНО:
ALTER TABLE media_files DROP CONSTRAINT media_files_telegram_file_id_key;

-- ДОБАВЛЕНО:
CREATE UNIQUE INDEX idx_media_files_telegram_file_id_unique 
ON media_files (telegram_file_id, request_number, category) 
WHERE status = 'active';
```

### 3. Исправление логики архивирования при замене
**Файл:** `app/services/media_storage.py`  
**Изменение:** Добавлено правильное сохранение изменений в БД при архивировании файлов.

```python
# ПРАВИЛЬНО:
async with get_async_db_context() as db:
    existing_file.status = "archived"
    existing_file.archived_at = datetime.now(timezone.utc)
    db.add(existing_file)
    await db.commit()
```
